# 任务：从零实现网页端井字棋游戏

在本目录（demo/tic_tac_toe）从零实现一个可在浏览器游玩的井字棋游戏（纯前端、无服务器），人机对战：玩家执 X 先手，电脑执 O，并补充单元测试。

## 功能规格

1. 文件结构：
   - index.html：3x3 棋盘（按钮或 div 均可）、当前回合与胜负提示、双方得分、"重新开始"按钮
   - game.js：游戏核心逻辑 + 渲染与输入（逻辑与渲染必须分离，见第 4 条）
   - style.css：页面样式（页面居中、棋盘清晰）
   - game.test.js：单元测试，使用 Node 内置的 node:test 与 node:assert，不引入任何第三方依赖
   - simulate.js：命令行模拟模式（验收用，见第 5 条）
2. 游戏规则：
   - 3x3 棋盘，玩家执 X 先手，电脑执 O。
   - 玩家点击空格落子；已有棋子的格子不可再点。
   - 每步之后判定：任意横线、竖线或两条对角线上三子相连则该方获胜；棋盘下满且无人获胜为平局。
   - 对局结束（胜负或平局）后棋盘锁定，需点"重新开始"开启新局；页面实时显示当前轮到谁、胜负结果与双方得分。
3. 电脑 AI（按固定优先级策略，不要求搜索算法）：
   1) 能赢则赢：AI 存在一步三连的机会，立即下在该位置。
   2) 否则堵玩家：玩家下一步能三连的位置，立即封堵；若有多个堵位，按"行优先"（y 小优先，同 y 按 x 小优先）取第一个。
   3) 否则优先下中心 (1,1)。
   4) 否则按顺序下角：(0,0)、(0,2)、(2,0)、(2,2)。
   5) 否则按顺序下边：(0,1)、(1,0)、(1,2)、(2,1)。
   - AI 落子前延迟 300ms（模拟思考，让画面可读）。
4. 逻辑与渲染分离（测试与验收的关键）：
   - 核心逻辑放在 `TicTacToe` 类（game.js 中）：棋盘状态、`play(x, y)`（玩家落子并返回本步结果）、`aiMove()`（按上述策略返回 AI 落子坐标）、`winner`、`isDraw`。
   - game.js 用 CommonJS 导出核心逻辑（`if (typeof module !== "undefined") module.exports = {...}`），让 Node 测试、命令行模拟与浏览器页面使用同一份代码。
5. 命令行模拟模式（验收必须）：
   - `node simulate.js <指令文件>`：逐行读取玩家落子坐标（每行形如 `x,y`），每步后打印棋盘与回合提示；玩家落子后自动执行一次 AI 落子并打印；对局结束或指令用完即打印最终胜负与得分并正常退出（退出码 0）。
6. 自测纪律（必须遵守）：
   - 只允许用 `node --test` 与 `node simulate.js demo_inputs.txt` 自测；禁止创建 debug*.js 之类的临时脚本。
   - 测试失败时先读报错与测试代码，理解原因后再修改 game.js；禁止不修改代码就重复运行同一命令。
   - 不要自己打开浏览器或启动服务器（本项目是纯静态页面）；完成后在总结中告诉用户用 `start index.html` 或双击 index.html 打开游玩。

## 实现提示（照做可避开绝大多数常见 bug）

- 棋盘用二维数组 `board[3][3]` 表示，`board[y][x]`；空格为 null，玩家为 "X"，电脑为 "O"。
- 胜负判定写一个独立函数 `checkWinner(board)`：把 3 行、3 列、2 条对角线共 8 个三元组收集起来逐一判断，避免遗漏对角线。
- 平局判定：棋盘无空格且 `checkWinner` 返回 null。
- 玩家落子前先判断 `board[y][x] === null` 且对局未结束，否则忽略该步。
- AI 优先级必须严格按第 3 条顺序实现；测试会按该顺序断言。
- 玩家恒为 X 且先手，AI 恒为 O。

## 验收标准

- `node --test` 全部通过，至少覆盖：合法落子、重复落子被拒、横线/竖线/两条对角线获胜判定、AI 能赢则赢、AI 封堵玩家、AI 优先中心与角、平局判定、对局结束后落子被拒。
- `node simulate.js demo_inputs.txt` 能逐帧打印一局完整对局（玩家获胜或平局均可），最后打印最终结果并正常退出（退出码 0）。
- 浏览器打开 index.html 可点击落子、AI 自动应子，胜负提示与重新开始正常。
