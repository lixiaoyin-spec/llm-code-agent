## 演示任务（可直接照录）

在仓库根目录运行（先配置好 ZHIPU_API_KEY 环境变量）：

```bash
python agent.py "给 wordfreq.py 增加一个 --top N 命令行参数：按词频从高到低只输出前 N 个词（默认输出全部），并补充对应的单元测试，运行测试确保全部通过" --workspace demo
```

- 执行过程中会出现 run_command 确认提示，按 y（或录制时加 --auto-approve 让画面更流畅，讲解时说明"生产默认人工确认，演示为流畅放行"）
- 预期过程（已用真实模型验证）：读文件 -> 修改 wordfreq.py -> 补充测试 -> 运行测试出现 1-2 次失败 -> agent 自行分析并修复 -> 全部通过 -> --help 与 --top 实测 -> 输出总结
- 这段"出错-自纠"恰好展示错误回传闭环，讲解时值得强调

## 讲解要点（对应面试高频问题）

- 主循环：每轮把"系统提示+历史+工具定义"发给模型；解析流式输出得到文本与工具调用；只读工具并行、写文件与命令按序串行执行；结果回传后进入下一轮；模型不再调用工具即任务结束
- 上下文管理：启发式 token 估算 -> 超预算把早期历史压缩成摘要、保留近期消息；压缩失败则继续跑不丢数据
- 终止条件：自然完成 / 轮数上限 / 连续 3 轮相同调用 / Ctrl+C / API 认证失败
- 错误处理：工具错误回传模型自纠；429/5xx 指数退避重试；auth 立即停止
- 安全：路径沙箱、命令人工确认、危险命令防呆拦截、输出截断
- 为什么不用框架：核心逻辑自研、行为可控可解释（详见 README.md "设计决策"）

## 录制注意事项

- 全程不得出现 API Key：Key 只放环境变量/本地配置，屏幕不要显示 .env 内容或 echo Key
- 建议：系统录屏/OBS + 麦克风；先录执行画面再配讲解音轨，执行段 2-4 倍加速
- mp4、不超过 200MB、总时长 2 分钟以内；可剪辑、可加速
- 录完把 demo 恢复现场（视频想重复录制时）：git restore demo/ ；或把 agent 的修复结果作为单独 commit 提交，也能体现真实产出
